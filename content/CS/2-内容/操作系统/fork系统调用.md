`fork()` 是 UNIX / Linux 操作系统中用于创建新 [[进程]] 的核心 [[系统调用]]。

核心机制流：
1. 完整克隆上下文：`fork()` 为子进程分配全新的 [[进程控制块]]（PCB），并完整复制父进程的虚拟地址空间（代码段、数据段、堆栈、文件描述符表及环境变量）。
2. 一次调用，两次返回：在父进程中返回新创建子进程的 PID（正整数）；在子进程中返回 $0$（标识自身为子进程）；若创建失败则返回负值（$-1$）。
3. 写时复制（Copy-On-Write，COW）：现代操作系统为避免昂贵的全量物理内存复制，调用 `fork()` 时父子进程共享同一批物理内存页，并将这些页的权限标记为“只读”。当任一方试图对页面执行写操作时，MMU 硬件触发缺页异常（Page Fault），内核介入分配全新的物理内存页并完成局部拷贝，实现读共享、写分离。

`fork()` 仅负责生成新进程实体；若需执行全新的程序二进制文件，子进程必须调用 `execve()` 彻底替换自身的代码段与数据段映像。

> [!faq]- 【代码题自测】分析以下程序的输出结果：</br>`int x = 1;`</br>`if (fork() == 0) { x++; exit(0); }`</br>`else { wait(NULL); printf("%d\n", x); }`</br>A. $2$</br>B. $1$</br>C. $0$</br>D. 产生未定义随机值
> 选 B。
> 
> 子进程对 `x` 的修改发生在独立的地址空间（或触发 COW 复制的新页面中），父进程的地址空间不受任何干扰。父进程经 `wait()` 同步等待子进程退出后，读取并打印自身地址空间中的 `x`，输出依然是初始值 $1$。

> [!faq]- 【14-15秋期末二·4】设某用户编制了如下源程序，经编译后在 Linux 下运行，此程序运行时，要占用（　）个 [[进程控制块]]（PCB）。</br>`main() {`</br>`    while (fork() == -1);`</br>`    while (fork() == -1);`</br>`    wait(0);`</br>`    wait(0);`</br>`}`</br>A. $1$</br>B. $2$</br>C. $3$</br>D. $4$
> 选 D。
> 
> `while (fork() == -1);` 表示不断重试直至成功创建 $1$ 个子进程。第 $1$ 行由初始父进程派生出 $1$ 个子进程（共 $2$ 个进程）；紧接着第 $2$ 行父子进程各自再成功执行一次 `fork()`，共产生 $2 \times 2 = 4$ 个进程，因此占用 $4$ 个 PCB。

> [!faq]- 【14-15秋期末二·12】在 Linux 操作系统中，`fork` 系统功能调用（　）。</br>A. 实现分支</br>B. 实现分叉</br>C. 实现创建子进程</br>D. 实现同步互斥
> 选 C。
> 
> `fork` 系统调用用于在内核中克隆当前进程上下文并创建新子进程。

> [!faq]- 【14-15秋期末三·6】判断正误：在 Linux 操作系统中，如果父进程终止退出，子进程、甚至子进程的子进程，包括整个进程家族都跟着终止退出。
> 错误（$\times$）。
> 
> 在 Linux 中，若父进程先于子进程终止退出，其子进程会变为孤儿进程，立即被 `init` 进程（$1$ 号进程）收养并继续独立运行，不会连带终止。
