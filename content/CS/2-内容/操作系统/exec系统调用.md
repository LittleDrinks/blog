```c
execlp("date", "date", NULL);
```

`exec` 丢弃当前进程的代码段、数据段与堆栈，装入新程序的映像，从新程序的 `main` 开始执行。

PID 与 PCB 保持不变，被替换的只是内存映像。`exec` 不创建新进程，它对同一进程更换执行的程序。这解释了成功时不返回的原因：原代码已被覆盖，返回值没有接收位置。只有失败时才返回 $-1$，典型原因为目标程序不存在，因此 `exec` 之后通常紧跟 `perror`。

保持不变的部分包括父进程关系、已打开的文件描述符、进程的 UID 与 GID。被替换的部分是原有代码定义的变量与函数、原堆与原栈。

`fork` 与 `exec` 的组合是 Shell 执行外部命令的完整机制：先复制出子进程，再让子进程替换为目标程序。Shell 自身不替换，因此命令执行结束后 Shell 仍可继续接收输入。内部命令（`cd`、`exit`）不执行 `fork`，原因是这类命令修改 Shell 自身状态，交给子进程修改的结果在子进程终止后丢失。

> [!faq]- 【实验三·思考题】子进程运行其他程序后，进程运行环境怎样变化？
> `exec` 用新程序的映像整体替换当前进程的代码段、数据段与堆栈，并从新程序的入口开始执行。
> 保持不变的是：PID、PCB、父进程关系、已打开的文件描述符、进程的 UID/GID。被替换掉的是：原有的代码、数据、堆和栈，以及原来代码里定义的变量与函数。
