直接通信方式下发送方必须指明接收者，但两个进程的执行速度不同。内核在两者之间设置队列，发送方写入后立即返回，接收方在需要时读取，速度差由队列缓冲。

实现方式是内核维护一组公共空闲消息缓冲区，每个进程的 [[进程控制块]] 中保存一条私有链表的头指针。

```c
typedef struct message_buffer {
    int sender;                  // 消息发送者进程标识
    int size;                    // 消息长度
    char *text;                  // 消息正文
    struct message_buffer *next; // 指向下一消息缓冲区
} message_buffer;
```

PCB 中配置三个成员：`mq` 为消息队列队首指针，`mutex` 为队列的互斥信号量（初值 $1$），`Sm` 为队列的计数信号量（初值 $0$），其数值为尚未被读取的消息条数。

`Send` 的步骤：从空闲池申请一块缓冲，把用户区 `a` 中的发送者、长度、正文复制到该缓冲，取得接收进程 PCB，执行 `P(receiver.mutex)` 锁定队列，把缓冲插入 `mq` 队尾，执行 `V(receiver.mutex)` 解锁，最后执行 `V(receiver.Sm)` 使消息计数加一。`Receive` 的步骤相反：先执行 `P(Sm)`，值为 $0$ 时队列为空，接收进程在此阻塞；有消息时执行 `P(mutex)` 锁定队列，从队首摘出消息并复制到用户区 `b`，执行 `V(mutex)`，归还缓冲区。

阻塞与唤醒分别由两个进程执行。接收方执行 `P(Sm)` 产生的阻塞是自身行为，唤醒它的 `V(Sm)` 由发送方在 `Send` 末尾执行。

与信箱通信的区别在寻址方式。消息缓冲队列属于直接通信，队列位于接收方 PCB 内部；信箱属于间接通信，信箱是独立系统对象，具有独立标识符，多个进程可向同一信箱投递与读取。
