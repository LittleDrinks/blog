Peterson 算法用纯软件手段实现临界区互斥，只需要两个共享变量：布尔数组 `flag[2]` 记录各进程的进入请求，整型变量 `turn` 记录同时请求时的裁决对象。

前三个软件算法的失效点各有不同。单标志法用 `turn` 强制两进程交替，一方退出后必须等对方进入一次才能再次进入，空闲让进不成立。双标志先检查法先读对方标志再写自身标志，两次访问之间存在间隙，双方可同时读到对方未请求，互斥不成立。双标志后检查法先写自身标志再读对方，双方可同时读到对方请求，两方都停在进入区，空闲让进与有限等待均不成立。

```c
bool flag[2] = {false, false};
int turn = 0;

/* 进入区，进程 i，另一进程记为 j */
flag[i] = true;                  /* 声明进入请求 */
turn = j;                        /* 把裁决权交给对方 */
while (flag[j] && turn == j);    /* 条件成立则不进入临界区 */
/* 临界区 */
flag[i] = false;                 /* 撤销请求 */
```

互斥的成立依据是 `turn` 的单值性。两进程同时请求时各自写 `turn`，写入顺序确定，最终值只有一个。设最终 `turn = j`，进程 i 的循环条件 `turn == j` 成立，i 停在进入区；进程 j 的条件 `turn == i` 不成立，j 进入临界区。后执行赋值的一方失去本次进入权，两者不可能同时通过。

空闲让进的成立依据是 `flag[j]`。对方无请求时 `flag[j]` 为假，循环条件整体为假，进程直接进入临界区，`turn` 的取值不影响结果。

四条准则的满足情况：互斥成立；空闲让进成立；有限等待成立，后写 `turn` 的一方获得进入权，等待不会无限延续；让权等待不成立，等待方在进入区反复执行循环判断，CPU 时间片照常消耗。四条准则里，让权等待是原则上应遵循但非必须的一条。纯软件实现的互斥算法中，它是满足前三条准则最完善的方案。

两个失效场景。一是等待方的循环测试持续消耗时间片，与 [[整型信号量]] 的忙等问题相同。二是现代处理器允许写操作重排，`turn = j` 可能先于 `flag[i] = true` 生效，互斥前提被破坏，实际实现需要在两次写之间插入内存屏障。教材把软件方法定性为有难度、局限性大、现在很少采用，原因即此。

> ![[王道习题原图/王道2.3单选36-程序.png]]
>
> **【答案】** C
>
> **【解析】** 根据Peterson算法的原理，可知（1）和（2）处分别为turn＝1和turn＝0。

> [!faq]- 【王道第二章 2.3 单选第37题】在Peterson算法中，flag数组的作用是（ ）。</br>A.表示每个线程是否想进入临界区</br>B.表示每个线程是否已进入临界区</br>C.表示每个线程是否已退出临界区</br>D.表示每个线程是否已完成任务
> **【答案】** A
>
> **【解析】** flag数组用于标记各个线程想进入临界区的意愿。当一个线程想要进入临界区时，它将自己对应的flag值置为true；当一个线程退出临界区时，它将自己对应的flag值置为false。这样，若两个进程都争着想进入临界区，则可以让进程将进入临界区的机会谦让给对方。

> [!faq]- 【王道第二章 2.3 单选第38题】在Peterson算法中，turn 变量的作用是（ ）。</br>A.表示轮到哪个线程进入临界区</br>B.表示哪个线程先发出访问请求</br>C.表示哪个线程后发出访问请求</br>D.表示哪个线程已进入临界区
> **【答案】** A
>
> **【解析】** turn变量用于指示允许进入临界区的线程编号。当一个线程想要进入临界区时，它将turn置为对方的编号，表示优先让对方先进入。当一个线程检查到对方的flag为 true时，表示对方也想进入，这时就需要根据turn来决定谁先进入。若tum等于自己的编号，表示轮到自己进入，则可以直接进入。若tum 等于对方的编号，表示轮到对方进入，则需等待对方退出。
