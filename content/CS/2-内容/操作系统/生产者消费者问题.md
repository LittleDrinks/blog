生产者—消费者问题是并发 [[进程]] 共享有界缓冲池的经典同步互斥模型。一组生产者进程向容量为 $n$ 的环形缓冲区写入数据，一组消费者进程从缓冲区读取数据。

核心约束与 [[记录型信号量]] 设置：
1. 同步约束：缓冲区满时生产者必须阻塞等待；缓冲区空时消费者必须阻塞等待。设置 `empty = n` 记录空闲槽位数，`full = 0` 记录已填充槽位数。
2. 互斥约束：缓冲池及队尾指针 `in`、队头指针 `out` 属于 [[临界资源]]，多个生产者之间或消费者之间严禁同时修改指针。设置互斥信号量初值为 $1$（可共用单一 `mutex = 1`，也可按读写分离设为生产者互斥锁 `p_mutex = 1` 与消费者互斥锁 `c_mutex = 1`）。
3. 死锁铁律：同步 `P(empty)` / `P(full)` 必须严格位于互斥 `P(mutex)` 之前。若先申请互斥锁再等待空闲槽位，当缓冲区满时生产者将持有互斥锁进入永久阻塞，消费者因拿不到锁无法取走数据腾出空间，直接触发 [[死锁]]。

除信号量外，操作系统也可采用 [[管程]] 集中管理共享缓冲池。管程作为一种实现进程同步互斥的抽象数据类型，由管程的名称、代表共享资源的数据结构说明、对数据结构进行操作的一组过程以及对共享数据设置初值的语句 $4$ 部分组成。

> [!faq]- 【14-15秋期末二·5】为了利用信号量实现临界区互斥，信号初值应该为（　）。</br>A. $1$</br>B. $2$</br>C. $4$</br>D. $8$
> 选 A。
> 
> 临界区在任意时刻仅允许 $1$ 个进程进入访问，因此互斥信号量的初值应设为 $1$。

> 选 B。
> 
> 生产者-消费者问题的本质是并发进程在共享有界缓冲区时的同步与互斥问题。

> ```c
> /* 生产者进程 */
> while (TRUE) {
>     生产一个产品;
>     P(empty);
>     P(p_mutex);
>     产品送往 buffer(in);
>     in = (in + 1) mod n;
>     V(p_mutex);
>     V(full);
> }
> 
> /* 消费者进程 */
> while (TRUE) {
>     P(full);
>     P(c_mutex);
>     从 buffer(out) 中取出产品;
>     out = (out + 1) mod n;
>     V(c_mutex);
>     V(empty);
> }
> ```

>         wait(full);       // 先申请满缓冲（同步信号量）

>         out = (out + 1) % n;
>         signal(mutex);
>         signal(empty);
>         consume the item in nextc;
>     } while (TRUE);
> }
>
