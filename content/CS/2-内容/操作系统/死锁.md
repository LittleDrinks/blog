死锁（Deadlock）指多个并发 [[进程]] 在运行过程中因争夺独占资源而造成的一种互相等待且无外力干预下永远无法向前推进的僵死状态。

产生死锁的四个必要条件（缺一不可）：
1. 互斥条件（Mutual Exclusion）：涉及的资源在一段时间内只能由一个进程独占访问，其他申请者必须排队等待。
2. 请求和保持条件（Hold and Wait）：进程已经保持了至少一个资源，但又提出新的资源申请，在申请受阻阻塞时，对自己已占有的资源绝不主动释放。
3. 不可剥夺条件（No Preemption）：进程已获得的资源在未主动使用完毕前，系统或第三方进程不能强行剥夺，只能由该进程自愿释放。
4. 环路等待条件（Circular Wait）：必然存在一个进程序列 $\{P_0, P_1, \dots, P_n\}$，其中 $P_0$ 等待 $P_1$ 占有的资源，$P_1$ 等待 $P_2$ 占有的资源，...，$P_n$ 等待 $P_0$ 占有的资源，形成闭合等待环链。

处理方法层级：
- 死锁预防：在设计系统静态规则时直接破坏四个必要条件之一（破坏环路等待最有效：资源线性编号申请）。
- 死锁避免：在动态分配资源前执行安全性检测（如 [[银行家算法]]）。
- 死锁检测与解除：允许发生死锁，依靠死锁检测算法（资源分配图简化与死锁定理）发现环路后强制撤销部分进程回收资源。

> [!faq]- 【真题自测】系统有 $3$ 个并发进程，若每个进程都需要申请 $2$ 台打印机，为保证系统绝不发生死锁，系统至少需要配置多少台打印机？
> 根据极端情况推导：若每个进程都占有了 $1$ 台打印机（共消耗 $3 \times 1 = 3$ 台），此时若系统还能再提供 $1$ 台打印机给任意一个进程，该进程即可满足需求并运行完毕释放 $2$ 台，带动其余进程完成。
> 
> 因此最少需要 $3 + 1 = 4$ 台打印机。

> [!faq]- 【第3章作业Q27】何谓死锁？产生死锁的原因和必要条件是什么？
> 定义：死锁指多个进程在运行过程中，因争夺资源而造成的一种僵局（相互等待），若无外力作用，这些进程都将永远无法向前推进。
> 
> 产生死锁的三大原因：
> 1. 竞争不可抢占性资源引起死锁。
> 2. 竞争可消耗资源引起死锁。
> 3. 进程推进顺序不当引起死锁。
> 
> 四个必要条件：
> 1. 互斥条件：一段时间内某资源只能被一个进程占用。
> 2. 请求和保持条件：进程已保持了至少一个资源，但又提出了新的资源请求，而该资源被其他进程占有，此时请求进程被阻塞，但对自己已获得的资源保持不放。
> 3. 不剥夺条件（不可抢占）：进程已获得的资源在未使用完之前不能被强行剥夺，只能由该进程自愿释放。
> 4. 循环等待条件（环路等待）：存在一个进程—资源的环形链，链中每一个进程都在等待下一个进程所占有的资源。

> [!faq]- 【第3章作业Q30】在教材 [[银行家算法]] 的例子中：$T_0$ 时刻经 $P_1$ 分配后 $\text{Available}=(2, 3, 0)$，各进程（Allocation / Need）分别为：</br>$P_0(0,1,0 / 7,4,3), P_1(3,0,2 / 0,2,0), P_2(3,0,2 / 6,0,0), P_3(2,1,1 / 0,1,1), P_4(0,0,2 / 4,3,1)$。</br>如果 $P_0$ 发出的请求向量由 $\text{Request}_0(0, 2, 0)$ 改为 $\text{Request}_0(0, 1, 0)$，问系统可否将资源分配给它？
> 可以分配。试探将 $(0, 1, 0)$ 分配给 $P_0$ 后，更新 $P_0$ 的 $\text{Allocation}_0 \gets (0, 2, 0)$、$\text{Need}_0 \gets (7, 3, 3)$，系统剩余可用资源 $\text{Available}_0 \gets (2, 2, 0)$。
> 
> 执行安全性检查：
> 1. 初始 $\text{Work} = (2, 2, 0)$，先满足 $P_1(\text{Need } 0, 2, 0 \le 2, 2, 0)$，执行完毕释放 $(3, 0, 2)$，更新 $\text{Work} \gets (5, 2, 2)$。
> 2. 满足 $P_3(\text{Need } 0, 1, 1 \le 5, 2, 2)$，执行完毕释放 $(2, 1, 1)$，更新 $\text{Work} \gets (7, 3, 3)$。
> 3. 满足 $P_4(\text{Need } 4, 3, 1 \le 7, 3, 3)$，执行完毕释放 $(0, 0, 2)$，更新 $\text{Work} \gets (7, 3, 5)$。
> 4. 满足 $P_0(\text{Need } 7, 3, 3 \le 7, 3, 5)$，执行完毕释放 $(0, 2, 0)$，更新 $\text{Work} \gets (7, 5, 5)$。
> 5. 满足 $P_2(\text{Need } 6, 0, 0 \le 7, 5, 5)$，执行完毕释放 $(3, 0, 2)$，更新 $\text{Work} \gets (10, 5, 7)$。
> 
> 存在安全序列 $\langle P_1, P_3, P_4, P_0, P_2 \rangle$，故系统可将 $\text{Request}_0(0, 1, 0)$ 安全分配给 $P_0$。

> [!faq]- 【第3章作业Q31】在 [[银行家算法]] 中，若出现下述四类资源（A、B、C、D）分配情况：初始 $\text{Available}=(1, 6, 2, 2)$，各进程（Allocation / Need）分别为：</br>$P_0(0,0,3,2 / 0,0,1,2)$、$P_1(1,0,0,0 / 1,7,5,0)$、$P_2(1,3,5,4 / 2,3,5,6)$、$P_3(0,3,3,2 / 0,6,5,2)$、$P_4(0,0,1,4 / 0,6,5,6)$。</br>试问：</br>（1）该状态是否安全？</br>（2）若进程 $P_2$ 提出请求 $\text{Request}_2(1, 2, 2, 2)$ 后，系统能否将资源分配给它？
> 1. 该状态是安全的。从初始 $\text{Work} = (1, 6, 2, 2)$ 出发，可按序列 $\langle P_0, P_3, P_4, P_1, P_2 \rangle$ 依次执行完毕并释放资源，工作向量推进过程为：
>    $$(1, 6, 2, 2) \xrightarrow{P_0} (1, 6, 5, 4) \xrightarrow{P_3} (1, 9, 8, 6) \xrightarrow{P_4} (1, 9, 9, 10) \xrightarrow{P_1} (2, 9, 9, 10) \xrightarrow{P_2} (3, 12, 14, 14)$$
>    存在安全序列，故系统处于安全状态。
> 
> 2. 无法分配，$P_2$ 必须等待：
>    - 合法性检查：$\text{Request}_2(1, 2, 2, 2) \le \text{Need}_2(2, 3, 5, 6)$ 且 $\text{Request}_2(1, 2, 2, 2) \le \text{Available}(1, 6, 2, 2)$，条件满足。
>    - 试探分配后：新的可用资源向量 $\text{Available}' = (1, 6, 2, 2) - (1, 2, 2, 2) = (0, 4, 0, 0)$，此时 $P_2$ 的 $\text{Need}_2' = (1, 1, 3, 4)$。
>    - 安全性检查：当前 $\text{Work} = (0, 4, 0, 0)$（可用 A、C、D 资源全为 $0$），而所有 $5$ 个进程的 $\text{Need}$ 向量对 A、C、D 至少有一项大于 $0$，没有任何一个进程满足 $\text{Need}_i \le (0, 4, 0, 0)$，所有进程的 $\text{Finish}$ 均为 $\times$。试探分配会导致系统进入不安全状态，因此不能分配给 $P_2$，$P_2$ 必须等待。
