系统调用（System Call）是操作系统提供给程序员在代码中请求内核服务的程序接口，是用户态通往 [[内核态]] 的唯一受控通道。

普通函数调用与系统调用的物理本质对比：

| 维度 | 普通函数调用（Library Call） | 系统调用（System Call） |
| :--- | :--- | :--- |
| 执行特权级 | 全程在用户态（Ring 3）运行 | 触发 CPU 特权级陷入内核态（Ring 0） |
| 底层指令 | 汇编 `call` 跳转 | 软中断指令（如 x86 `syscall`、`int $0x80` 或 UNIX `CHMK`） |
| 寻址空间 | 仅限于当前进程的虚拟私有地址空间 | 跨越特权级寻址受保护的内核物理地址空间 |
| 返回机制 | `ret` 恢复栈帧返回 | 中断返回（`sysret`），返回前可能触发处理机调度重新分派 |

完整陷入硬件执行流：
1. 参数打包：用户库函数将系统调用号填入指定寄存器（如 Linux 的 `eax`/`rax`），参数通过陷入指令自带、通用寄存器或内存参数表传递。
2. 硬件陷入（Trap）：执行陷入指令，硬件自动将处理机状态长字（PSL/PSW）与程序计数器（PC）压入用户核心栈，特权级切换为内核态，跳转至汇编总控程序 `trap.S`。
3. 分派与参数审查：`trap.S` 保存通用寄存器现场并维护参数表指针 `AP` 与栈帧指针 `FP` 后调用 `trap.C`；`trap.C` 将参数从用户区传入 `U.u_arg`，依据系统调用号检索系统调用定义表 `Sysent[]`（`sys_call_table`），跳转至具体的内核服务子程序。
4. 中断恢复与再调度检查：服务例程返回 `trap.C` 后，系统重新计算进程的动态优先级并检查再调度标志（若置位则调用 `switch` 切换进程），最后回到 `trap.S` 恢复现场并切回用户态。

> [!faq]- 【第9章作业Q19】试说明系统调用的处理步骤。
> 系统调用的典型处理步骤分为以下四个阶段：
> 1. 准备与参数传递：用户程序在调用库函数时，将系统调用号和参数放入指定的通用寄存器（如 `EAX`）或内存参数表/用户栈中。
> 2. 陷入内核：用户程序执行软中断/陷入指令（如 `CHMK`、`INT 80h` 或 `syscall`），由硬件自动保存当前程序计数器（PC）和程序状态字（PSW/PSL），CPU 状态由用户态切换为核心态，控制权转交给陷入总控程序。
> 3. 分发与执行：内核根据系统调用号查询系统调用定义表，找到对应的服务例程入口地址并跳转执行，完成具体的内核功能。
> 4. 恢复现场并返回：核心服务例程执行完毕后将结果或状态码存入约定寄存器，执行返回前的优先级重算与再调度检查，恢复被中断进程的现场上下文，执行中断返回指令切回用户态。

> [!faq]- 【第9章作业Q23】`trap.S` 是什么程序？它完成哪些主要功能？
> 性质：`trap.S` 是 UNIX 系统内核中用汇编语言编写的底层中断与陷入（异常）总控程序。
> 
> 主要功能：
> 1. 保护现场：捕获系统调用或异常时，把 CPU 在用户态下的通用寄存器、参数表指针 `AP`、栈帧指针 `FP` 等上下文压入用户核心栈中保存。
> 2. 设置内核运行环境：建立核心态堆栈指针，做好调用高级语言所必需的栈对齐与参数布局。
> 3. 转入高层处理例程：将陷入类型和上下文指针作为参数，调用 C 语言编写的陷入分发总控程序 `trap.C`。
> 4. 恢复现场与返回：在高层处理函数执行完毕后，从内核栈恢复各寄存器的值，执行中断返回指令，使 CPU 返回用户态继续执行。

> [!faq]- 【第9章作业Q25】`trap.C` 是什么程序？它将完成哪些处理？
> 性质：`trap.C` 是系统调用和陷入处理的高层 C 语言控制与分发程序。
> 
> 主要处理：
> 1. 识别陷入类型与确定系统调用号：依据底层 `trap.S` 传入的参数，区分本次陷入是系统调用、缺页异常还是硬件故障，并提取系统调用号。
> 2. 参数传送：将系统调用参数表中的内容从用户区传送到 User 结构的 `U.u_arg` 中，供系统调用处理子程序使用。
> 3. 分发并调用内核服务例程：依据系统调用号检索系统调用定义表 `Sysent[]`，转入对应的底层内核处理子程序（如 `sys_open`、`sys_read` 等）。
> 4. 系统调用返回前的公共处理：将返回值写入寄存器结构；重新计算进程的动态优先级；检查再调度标志（若置位则调用 `switch` 调度程序切换进程）以及处理挂起的软中断信号。

> [!faq]- 【第9章作业Q26】为方便转入系统调用处理程序，在 UNIX 系统中配置了什么样的数据结构？
> UNIX 系统中配置了系统调用定义表（`Sysent[]` / `sys_call_table`）：
> 1. 结构形式：本质上是一个以系统调用号为索引的结构体/函数指针数组。
> 2. 表项内容：每个表项记录了对应系统调用处理子程序在内核中的入口地址，以及该系统调用所需参数的个数和字节规格。
> 3. 作用：发生系统调用时，内核无需通过多重条件分支判断，直接以系统调用号作为下标 $O(1)$ 寻址该表，即可快速跳转到相应的内核服务程序执行。

用户程序无法用 `jmp` 或 `call` 直接跳入内核地址空间执行服务：页表项中的用户/超级用户位限制用户态访问内核页，越权访问触发通用保护性异常（#GP）并终止进程；只有陷入指令能完成受控的特权级切换。

> [!faq]- 【王道第一章 1.3 单选第31题】【2022统考真题】执行系统调用的过程涉及下列操作，其中由操作系统完成的是（ ）。I. 保存断点和程序状态字</br>Ⅱ. 保存通用寄存器的内容</br>Ⅱ.执行系统调用服务例程</br>Ⅳ.将CPU模式改为内核态</br>A.仅I、Ⅲ</br>B.仅Ⅱ、Ⅲ</br>C.仅Ⅱ、Ⅳ</br>D.仅Ⅱ、Ⅲ、Ⅳ
> **【答案】** B
>
> **【解析】** 发生系统调用时，CPU通过执行软中断指令将CPU的运行状态从用户态切换到内核态，这个过程与中断和异常的响应过程相同，由硬件负责保存断点和程序状态字，并将CPU模式改为内核态。然后，执行操作系统内核的系统调用入口程序，该内核程序负责保存通用寄存器的内容，再调用执行特定的系统调用服务例程。综上，说法I、Ⅳ由硬件完成，说法Ⅱ、Ⅲ由操作系统完成。

> [!faq]- 【王道第一章 1.3 单选第33题】【2024统考真题】下列关于中断、异常和系统调用的叙述中，错误的是（ ）。</br>A.中断或异常发生时，CPU处于内核态</br>B.每个系统调用都有对应的内核服务例程</br>C.中断处理程序开始执行时，CPU处于内核态</br>D.系统添加新类型设备时，需要注册相应的中断服务例程
> **【答案】** A
>
> **【解析】** 当中断或异常发生时，CPU既可能处于内核态，又可能处于用户态，具体取决于当时CPU正在处理的任务，选项A错误。不同的系统调用对应不同的内核服务例程，选项B正确。在中断响应阶段，若CPU处于用户态，则需要切换到内核态，因此在中断处理阶段，CPU一定处于内核态，选项C正确。设备种类繁多，计算机不可能事先准备好所有设备对应的中断服务例程（实际上属于设备驱动程序），因此当系统添加新类型的设备时，需要注册相应的中断服务例程。

访管指令（Trap 指令）是一条可在用户态执行的特殊指令，执行后产生访管中断，使处理机进入内核态。它本身不是特权指令，作用是为用户程序提供一个受控且主动的内核态入口。系统调用正是通过访管指令实现的，这也是「用户态到内核态的三条途径」中唯一由程序主动发起的一条。
