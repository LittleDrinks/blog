预防死锁的一种算法

> [!faq]- 【14-15 秋期末三·5】判断正误：[[银行家算法]] 广泛应用于各种操作系统中用于解决死锁问题。
> 错误（$\times$）。
> 
> 银行家算法要求所有进程预先声明最大资源需求量且进程数与资源数保持固定，现实通用操作系统中无法满足该先验假设，因此极少在实际系统中广泛使用。


> [!info] Assumption
> 核心数据结构：
> - 可用资源向量：$\text{Available}[m]$
> - 最大需求矩阵：$\text{Max}[n][m]$
> - 已分配矩阵：$\text{Allocation}[n][m]$
> - 尚需资源矩阵：$\text{Need}[n][m] = \text{Max}[n][m] - \text{Allocation}[n][m]$
> 
> 系统在运行的时候，某些进程可能动态申请，一次申请一部分的某种资源
> 
> 这些申请的资源随着运行可能持续占有、也可能释放一部分
> 
> 但如果某个进程已经获得了它最大所需的资源数量，那他就一定会运行完并把这些资源释放

死锁就是指两个进程相互卡死，形成类似环形的结构。于是我们用一种线性的结构定义**安全状态**，即能够找到一种顺序运行完所有的进程。
安全状态是一定不会死锁的状态，不安全状态是可能滑向死锁的状态

> [!faq]- 系统处于“不安全状态”是否等价于“已经发生死锁”？
> 不等价。安全状态确保系统一定可以找到完成序列，因而绝对无死锁；不安全状态只表明系统失去了让全部进程顺利执行完毕的安全保障，但只有当后续并发进程继续申请资源并超出现存配额时，才会真正滑向死锁。

> [!faq]- 系统有 $3$ 个并发进程，若每个进程都需要申请 $2$ 台打印机，为保证系统绝不发生死锁，系统至少需要配置多少台打印机？
> 根据极端情况推导：若每个进程都占有了 $1$ 台打印机（共消耗 $3 \times 1 = 3$ 台），此时若系统还能再提供 $1$ 台打印机给任意一个进程，该进程即可满足需求并运行完毕释放 $2$ 台，带动其余进程完成。
> 
> 因此最少需要 $3 + 1 = 4$ 台打印机。
> [!faq]- 【第 3 章作业 Q 30】在教材[[银行家算法]] 的例子中：$T_0$ 时刻经 $P_1$ 分配后 $\text{Available}=(2, 3, 0)$，各进程（Allocation / Need）分别为：</br>$P_0(0,1,0 / 7,4,3), P_1(3,0,2 / 0,2,0), P_2(3,0,2 / 6,0,0), P_3(2,1,1 / 0,1,1), P_4(0,0,2 / 4,3,1)$。</br>如果 $P_0$ 发出的请求向量由 $\text{Request}_0(0, 2, 0)$ 改为 $\text{Request}_0(0, 1, 0)$，问系统可否将资源分配给它？
> 可以分配。试探将 $(0, 1, 0)$ 分配给 $P_0$ 后，更新 $P_0$ 的 $\text{Allocation}_0 \gets (0, 2, 0)$、$\text{Need}_0 \gets (7, 3, 3)$，系统剩余可用资源 $\text{Available}_0 \gets (2, 2, 0)$。
> 
> 执行安全性检查：
> 1. 初始 $\text{Work} = (2, 2, 0)$，先满足 $P_1(\text{Need } 0, 2, 0 \le 2, 2, 0)$，执行完毕释放 $(3, 0, 2)$，更新 $\text{Work} \gets (5, 2, 2)$。
> 2. 满足 $P_3(\text{Need } 0, 1, 1 \le 5, 2, 2)$，执行完毕释放 $(2, 1, 1)$，更新 $\text{Work} \gets (7, 3, 3)$。
> 3. 满足 $P_4(\text{Need } 4, 3, 1 \le 7, 3, 3)$，执行完毕释放 $(0, 0, 2)$，更新 $\text{Work} \gets (7, 3, 5)$。
> 4. 满足 $P_0(\text{Need } 7, 3, 3 \le 7, 3, 5)$，执行完毕释放 $(0, 2, 0)$，更新 $\text{Work} \gets (7, 5, 5)$。
> 5. 满足 $P_2(\text{Need } 6, 0, 0 \le 7, 5, 5)$，执行完毕释放 $(3, 0, 2)$，更新 $\text{Work} \gets (10, 5, 7)$。
> 
> 存在安全序列 $\langle P_1, P_3, P_4, P_0, P_2 \rangle$，故系统可将 $\text{Request}_0(0, 1, 0)$ 安全分配给 $P_0$。

为了防止死锁，我们需要在最坏情况下做反事实检验，即每次进程向系统申请资源的时候，除非它已经满足了最大需求（一定会运行到底并释放），否则我们就假设进程不会返还这部分资源。在此基础上判断：这个状态是否安全（也就是是否能找到一种顺序完成所有的进程）

整体流程：

1. 合法性检验：若 $\text{Request}_i \le \text{Need}_i$ 且 $\text{Request}_i \le \text{Available}$，允许进行试探分配；否则拒绝分配。
2. 试探分配   $$\begin{aligned}
   \text{Available}' &= \text{Available} - \text{Request}_i \\
   \text{Allocation}_i' &= \text{Allocation}_i + \text{Request}_i \\
   \text{Need}_i' &= \text{Need}_i - \text{Request}_i
   \end{aligned}$$
3. 安全性算法（Safety Check）：
   - 设工作向量 $\text{Work} = \text{Available}'$，标记向量 $\text{Finish}[i] = \text{false}$。
   - 在尚未完成的进程中寻找满足 $\text{Need}_k \le \text{Work}$ 的进程 $P_k$。
   - 若找到，假设 $P_k$ 运行完毕释放资源：$\text{Work} = \text{Work} + \text{Allocation}_k$，$\text{Finish}[k] = \text{true}$。
   - 重复上述步骤。若所有进程均满足 $\text{Finish} = \text{true}$，说明系统存在一条**安全序列**，当前状态安全，正式分配；否则判定分配将导致系统进入不安全状态，拒绝分配并令进程等待。

> [!faq]- 【第 3 章作业 Q 31】在[[银行家算法]] 中，若出现下述四类资源（A、B、C、D）分配情况：初始 $\text{Available}=(1, 6, 2, 2)$，各进程（Allocation / Need）分别为：</br>$P_0(0,0,3,2 / 0,0,1,2)$、$P_1(1,0,0,0 / 1,7,5,0)$、$P_2(1,3,5,4 / 2,3,5,6)$、$P_3(0,3,3,2 / 0,6,5,2)$、$P_4(0,0,1,4 / 0,6,5,6)$。</br>试问：</br>（1）该状态是否安全？</br>（2）若进程 $P_2$ 提出请求 $\text{Request}_2(1, 2, 2, 2)$ 后，系统能否将资源分配给它？
> 6. 该状态是安全的。从初始 $\text{Work} = (1, 6, 2, 2)$ 出发，可按序列 $\langle P_0, P_3, P_4, P_1, P_2 \rangle$ 依次执行完毕并释放资源，工作向量推进过程为：
>    $$(1, 6, 2, 2) \xrightarrow{P_0} (1, 6, 5, 4) \xrightarrow{P_3} (1, 9, 8, 6) \xrightarrow{P_4} (1, 9, 9, 10) \xrightarrow{P_1} (2, 9, 9, 10) \xrightarrow{P_2} (3, 12, 14, 14)$$
>    存在安全序列，故系统处于安全状态。
> 
> 7. 无法分配，$P_2$ 必须等待：
>    - 合法性检查：$\text{Request}_2(1, 2, 2, 2) \le \text{Need}_2(2, 3, 5, 6)$ 且 $\text{Request}_2(1, 2, 2, 2) \le \text{Available}(1, 6, 2, 2)$，条件满足。
>    - 试探分配后：新的可用资源向量 $\text{Available}' = (1, 6, 2, 2) - (1, 2, 2, 2) = (0, 4, 0, 0)$，此时 $P_2$ 的 $\text{Need}_2' = (1, 1, 3, 4)$。
>    - 安全性检查：当前 $\text{Work} = (0, 4, 0, 0)$（可用 A、C、D 资源全为 $0$），而所有 $5$ 个进程的 $\text{Need}$ 向量对 A、C、D 至少有一项大于 $0$，没有任何一个进程满足 $\text{Need}_i \le (0, 4, 0, 0)$，所有进程的 $\text{Finish}$ 均为 $\times$。试探分配会导致系统进入不安全状态，因此不能分配给 $P_2$，$P_2$ 必须等待。

> [!faq]- 【14-15 秋期末八】设在 $T$ 时刻，系统中有 $5$ 个进程，三种资源 A、B、C 的使用情况如下：</br>$P_0\text{ (Max: }1,3,3\text{; Need: }1,2,2)$，$P_1\text{ (Max: }3,2,2\text{; Need: }2,2,1)$，$P_2\text{ (Max: }2,2,1\text{; Need: }2,1,1)$，$P_3\text{ (Max: }2,0,2\text{; Need: }1,0,1)$，$P_4\text{ (Max: }2,4,3\text{; Need: }2,3,3)$，当前系统空闲资源 $\text{Available} = (2, 2, 1)$。</br>各小题相互独立，用[[银行家算法]] 判断能否分配并写出步骤（$12$ 分）：</br>（1）$P_3$ 申请 $(2, 0, 0)$，能否分配？为什么？</br>（2）$P_1$ 申请 $(0, 0, 2)$，能否分配？为什么？</br>（3）$P_2$ 申请 $(1, 1, 1)$，能否分配？为什么？
> 由 $\text{Allocation} = \text{Max} - \text{Need}$ 可得当前已分配矩阵：$P_0=(0,1,1), P_1=(1,0,1), P_2=(0,1,0), P_3=(1,0,1), P_4=(0,1,0)$。
> 
> 1. $P_3$ 申请 $(2, 0, 0)$：否。因为 $P_3$ 的请求 $(2, 0, 0) > \text{Need}_{P_3}(1, 0, 1)$，超出其宣布的最大需求。
> 2. $P_1$ 申请 $(0, 0, 2)$：否。因为 $P_1$ 的请求 $(0, 0, 2) > \text{Available}(2, 2, 1)$，当前可用资源不足，进程必须等待。
> 3. $P_2$ 申请 $(1, 1, 1)$：能。因为 $P_2$ 的请求 $(1, 1, 1) \le \text{Need}_{P_2}(2, 1, 1)$ 且 $\le \text{Available}(2, 2, 1)$。试探性预分配后，更新 $\text{Available} \gets (1, 1, 0)$，$\text{Allocation}_{P_2} \gets (1, 2, 1)$，$\text{Need}_{P_2} \gets (1, 0, 0)$。
>    （注：原卷评分标准将 $P_3$ 的 $\text{Need}$ 印作 $(1,1,0)$ 并给出安全序列 $\langle P_3, P_2, P_1, P_0, P_4 \rangle$；若严格按题干 $\text{Need}_{P_3}=(1,0,1)$ 与预分配后的 $\text{Need}_{P_2}=(1,0,0)$ 推导，初始 $\text{Work}=(1,1,0)$ 可先满足 $P_2$ 执行完毕释放 $(1,2,1)$ 使 $\text{Work} \gets (2,3,1)$，随后依次满足 $P_3 \to P_1 \to P_0 \to P_4$，存在安全序列 $\langle P_2, P_3, P_1, P_0, P_4 \rangle$，分配后状态安全。）
