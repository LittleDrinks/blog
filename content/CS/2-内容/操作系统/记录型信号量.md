# 记录型信号量

整型信号量由于缺乏阻塞队列，进程在等待锁时会不断循环测试，陷入“忙等”状态，违背让权等待原则。记录型信号量（Counting Semaphore）通过引入资源计数值与等待进程队列指针，完美实现了让权等待。

数据结构定义：
```c
typedef struct {
    int value;               // 资源计数器：> 0 表示可用资源数；< 0 其绝对值代表阻塞队列中的进程数
    struct process *list;    // 等待该资源的进程 PCB 链表
} semaphore;
```

原语实现：
```c
void wait(semaphore *S) {    // P 原语
    S->value--;
    if (S->value < 0) {
        block(S->list);      // 资源耗尽，调用阻塞原语自我挂起并让出 CPU
    }
}

void signal(semaphore *S) {  // V 原语
    S->value++;
    if (S->value <= 0) {
        wakeup(S->list);     // 尚有进程排队，唤醒队列首个进程进入就绪态
    }
}
```

$P$ 与 $V$ 必须是原子操作，由关中断或硬件测试并设置指令（TS / CAS）保障不可分割性。

> [!faq]- 【概念自测】某信号量 $S$ 的初值为 $3$，当前值为 $-2$，请问此时系统中有几个可用资源？有几个进程在等待该资源？
> 当前可用资源数为 $0$ 个（因为已小于等于 $0$）；等待队列中有 $|-2| = 2$ 个进程处于阻塞挂起状态。
