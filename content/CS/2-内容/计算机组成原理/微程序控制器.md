核心思想：用软件方法设计硬件——把控制信号编成微指令存入控制存储器（CM），运行时从控存取出微指令产生控制信号

微命令：最小单位，控制部件向执行部件发出的控制命令，与微操作一一对应
微操作：执行部件接受微命令后所进行的操作
微指令：同一 T 周期内并行执行的微命令组合
微程序：若干微指令有序集合
1条机器指令 = 1段微程序 = 若干条微指令

相容微操作（可并行）→ 各占一位直接控制；
互斥微操作（不可并行）→ 可编码表示

| 部件 | 功能 |
|------|------|
| 控制存储器 μCM | 存放全部微程序（核心部件） |
| 微指令寄存器 μIR | 存放当前微指令 |
| 微地址形成部件 | 产生初始/后继微地址 |
| 微地址寄存器 μMAR | 接受微地址 |

工作流程：取指微程序（CM的0号单元）→ 操作码形成微程序入口 → 逐条执行微指令 → 回到取指微程序入口

微指令格式 = 操作控制字段 + 顺序控制字段

| | 水平型 | 垂直型 |
|---|--------|--------|
| 并行性 | 强 | 弱 |
| 执行速度 | 快 | 慢 |
| 微指令字长 | 长 | 短 |
| 微程序长度 | 短 | 长 |

编码方法：直接表示法（一位一命令，快但字长）→ 编码表示法（互斥命令分组编码，短但慢）→ 混合表示法（折中）

微地址形成：计数器方式（μMAR+1，简单但不能多路转移）vs 多路转移方式（修改μMAR某些位，灵活）

微地址转移逻辑例题：μA5-μA0共6位，P1按IR3-IR0做16路分支修改μA3-μA0，P2按进位C做2路分支修改μA0，P3按IR4-IR5做4路分支修改μA5-μA4
μA0 = P1·IR0·T4 + P2·C·T4（两个条件叠加，用与或非门）

> [!faq] 控制存储器存放什么？
> 微程序（不是机器指令，机器指令在主存）

> [!faq] 微命令和微操作什么关系？
> 一一对应

> [!faq] 取指微程序入口地址？
> CM的0号单元
