# 微程序控制器

## 核心思想

**微程序设计技术是用软件方法来设计硬件的技术。**

基本思想：把操作控制信号编制成**微指令**，存放到**控制存储器（CM）**里。运行时，从控存中取出微指令，产生指令运行所需的操作控制信号。

> [!tip]
> 简单理解：机器指令太复杂，把它拆成很多小步骤（微操作），每个小步骤用一个微指令控制，很多微指令合起来就是一段微程序。

## 基本概念层级（必背！）

| 概念 | 定义 | 关系 |
|------|------|------|
| **微命令** | 控制部件向执行部件发出的各种控制命令，是构成控制序列的**最小单位** | 微命令 → 控制微操作 |
| **微操作** | 微命令的操作过程 | 微操作是微命令的执行结果，**一一对应** |
| **微指令** | 把同一个 T 周期内**并行执行**的微操作控制信息存储在控存中，称为一条微指令 | 微命令的组合 |
| **微程序** | 一系列微指令的有序集合 | **1 条机器指令 = 1 段微程序** |
| **微地址** | 存放微指令的控制存储器单元地址 | 微指令在 CM 中的"门牌号" |

> [!warning]
> 考试必考：**1 条机器指令对应 1 段微程序**！不要记成 1 条微指令对应 1 条机器指令。

### 相容性与互斥性

- **相容微操作**：能够同时或在同一个节拍内并行执行的微操作 → 必须**各占一位**（直接控制）
- **互斥微操作**：不能同时或不能在同一个节拍内并行执行的微操作 → 可以**编码**表示

## 微程序控制器的组成框图

```
┌─────────────────────────────────────────────────────────────┐
│                      微程序控制器                            │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐                │
│  │ 控制存储器│   │ 微地址形成│   │ 微指令寄存器│                │
│  │  (μCM)   │   │  部件    │   │   (μIR)   │                │
│  └────┬─────┘   └────┬─────┘   └────┬─────┘                │
│       │              │              │                      │
│  ┌────┴──────────────┴──────────────┴────┐                 │
│  │           微指令译码器（产生控制信号）   │                 │
│  └────────────────────────────────────────┘                 │
└─────────────────────────────────────────────────────────────┘
```

### 各部件功能

| 部件 | 符号 | 功能 |
|------|------|------|
| **控制存储器** | μCM | 存放全部微程序，是微程序控制器的**核心部件** |
| **微指令寄存器** | μIR | 存放从 μCM 取出的当前正在执行的微指令 |
| **微地址形成部件** | — | 产生初始微地址和后继微地址 |
| **微地址寄存器** | μMAR | 接受微地址，为从 μCM 读下一条微指令做准备 |

## 微程序控制器的工作流程

1. **取机器指令的公共操作**：由一段**取指微程序**完成。机器启动时，自动将取指微程序入口地址（一般为 μCM 的 **0 号单元**）送 μMAR，读出微指令执行。执行完后，机器指令已存入 IR。
2. **形成微程序入口**：由机器指令的**操作码字段**通过微地址形成部件，产生该机器指令对应微程序的入口地址，送入 μMAR。
3. **执行微程序**：从 μCM 中逐条取出对应的微指令并执行，每条微指令都能自动产生下一条微指令的地址。
4. **返回取指**：一条机器指令对应的微程序执行完毕后，下一条微指令地址又回到**取指微程序的入口地址**，继续取下一台机器指令。

> [!tip]
> 循环往复：取指微程序 → 机器指令译码 → 执行对应微程序 → 回到取指微程序...

## 微指令的格式

一条微指令通常包含两大部分：

1. **操作控制字段（微操作码字段）**：产生某一步操作所需的各个微操作控制信号。某位为 1，表示发出该微命令。
2. **顺序控制字段（微地址码字段）**：控制产生下一条要执行的微指令地址。

### 水平型微指令

**定义**：一次能定义并能**并行执行多个微命令**的微指令。

**特点**：
- 并行操作能力强、效率高、灵活性强
- 执行一条指令的时间短
- 微指令字**较长**，但微程序**较短**
- 用户难以掌握

### 垂直型微指令

**定义**：采用编码方式，一次只能执行**一到两个微命令**的微指令。

**特点**：
- 并行操作能力差、效率较低
- 执行时间较长
- 微指令字**较短**，但微程序**较长**
- 与机器指令格式相似，比较容易掌握

### 水平型 vs 垂直型对比表（考试重点！）

| 特性 | 水平型微指令 | 垂直型微指令 |
|------|-------------|-------------|
| 并行性 | **强** | 弱 |
| 执行速度 | **快** | 慢 |
| 微指令字长 | **长** | 短 |
| 微程序长度 | **短** | 长 |
| 硬件复杂度 | **高** | 低 |
| 编程难度 | **难** | 易 |

## 微命令的编码方法

### 1. 直接表示法

操作控制字段中的**各位分别直接控制**计算机，不需要译码。

- 优点：简单直观，并行性强，速度快
- 缺点：微指令字太长

### 2. 编码表示法

将操作控制字段分为若干小段，每段内采用**最短编码法**，段与段之间采用**直接控制法**。

- 优点：可以避免互斥，使微指令字大大缩短
- 缺点：增加了译码电路，微程序执行速度减慢

### 3. 混合表示法

将前两种方法结合。某些编码不能独立定义微命令，需要与其他字段联合定义。

- 优点：兼顾两者特点，折中方案

## 微地址的形成方法

### 1. 计数器方式

**方法**：微程序顺序执行时，后继微地址 = 现行微地址 + 1（增量通常为 1）。遇到转移时，由微指令的转移地址段来形成转移微地址。

通常将 **μMAR 当作 μPC** 使用。

- **优点**：简单、易于掌握，编制微程序容易
- **缺点**：不能实现**两路以上的并行微程序转移**，不利于提高执行速度

### 2. 多路转移方式

**方法**：根据**状态条件 / 测试字段 / 微指令中的微地址 / 操作码**等因素，直接修改微地址寄存器的某些位，实现多路分支。

**特点**：可以实现多条件、多路分支转移，灵活性高。

> [!tip]
> 典型例子：机器指令操作码有 16 种，取指后按 IR 的 OP 字段进行 **16 路分支**，进入不同的微程序入口。

## 微地址转移逻辑例题（必考！）

> [!warning]
> 多路转移方式是考试**高频考点**，常考设计微地址转移逻辑表达式！

### 例题：微地址转移逻辑设计

**题目**：微地址寄存器有6位(μA5-μA0)，当需要修改其内容时，可通过某一位触发器的强置端S将其置"1"。现有三种情况：
1. 执行"取指"微指令后，微程序按IR的OP字段(IR3-IR0)进行16路分支；
2. 执行条件转移指令微程序时，按进位标志C的状态进行2路分支；
3. 执行控制台指令微程序时，按IR4，IR5的状态进行4路分支。

请按多路转移方法设计微地址转移逻辑。

**解答**：

#### 分析与分配

微程序有三种判别测试，分别为P1, P2, P3：

| 测试 | 条件 | 修改位 |
|------|------|--------|
| P1 | IR3-IR0（16路分支） | μA3-μA0 |
| P2 | 进位标志C（2路分支） | μA0 |
| P3 | IR4, IR5（4路分支） | μA5, μA4 |

#### 转移逻辑表达式

考虑时间因素T4（假设为CPU周期最后一个节拍脉冲）：

```
μA5 = P3 · IR5 · T4
μA4 = P3 · IR4 · T4
μA3 = P1 · IR3 · T4
μA2 = P1 · IR2 · T4
μA1 = P1 · IR1 · T4
μA0 = P1 · IR0 · T4 + P2 · C · T4
```

#### 实现说明

- 前5个表达式可用"与非"门实现
- 最后一个表达式用"与或非"门实现
- 从触发器强置端修改

> [!tip]
> **关键理解**：多路转移通过**修改微地址寄存器的某些位**来实现分支，测试信号(P1/P2/P3)用来选择当前进行哪种类型的分支判断。

## 微程序设计完整例题

### 例题：十进制加法指令的微程序设计

**题目**：设计十进制加法指令的微程序，写出各微指令内容。

**解答**：

假设十进制加法指令需要4条微指令完成：

| 微地址 | 微指令操作控制字段 | 功能说明 |
|--------|-------------------|----------|
| 001 | PC→AR, Read | 取指令地址 |
| 002 | MDR→IR, PC+1 | 读入指令，PC加1 |
| 003 | R1→Y, R2→X, Add | 取操作数，ALU加法 |
| 004 | ALU→R1, End | 结果送R1，结束回到取指 |

**微指令编码示意**：

```
微指令格式：[操作控制字段(若干位)] [下址字段] [判别测试字段]

001号微指令：[PCout, ARin, Read] [002] [0]
002号微指令：[MDRout, IRin, PC+1] [003] [P1]  ; P1表示操作码判别
003号微指令：[R1out, R2out, ALUop=ADD] [004] [0]
004号微指令：[ALUout, R1in] [000] [0]  ; 回到取指微程序入口
```

## 机器指令与微指令的关系

```
1 条机器指令  =  1 段微程序  =  若干条微指令
```

- **机器指令**：程序员编写，存放在**主存**中
- **微指令**：硬件设计者编制，存放在**控制存储器（CM）**中
- **机器指令的操作码**决定调用哪一段微程序

### CPU周期与微指令周期的关系

| 时间单位 | 关系 |
|----------|------|
| **微指令周期** | 从控存读取一条微指令并执行的时间 |
| **CPU周期** | 通常等于一个微指令周期 |
| **时钟周期** | 微指令周期内用于定时微操作的节拍 |

> [!tip]
> 一般设计：**一个微指令周期 = 一个CPU周期**，包含若干时钟周期。

## 动态微程序设计

- **静态微程序设计**：微程序设计好后一般无需改变，用 ROM 作控存
- **动态微程序设计**：用 EPROM 作控存，可以通过改变微指令和微程序来改变机器的指令系统

> [!warning]
> 微程序控制器因为**需要访问控制存储器取微指令**，所以速度比硬布线控制器慢。但优点是规整性好、易于修改和扩展。

## 本章考试常见题型

### 一、选择题

> [!faq] 微程序控制器中，控制存储器用来存放？</br>A. 机器指令</br>B. 微指令</br>C. 微程序</br>D. 数据
> C。控制存储器（CM）用于存放**全部微程序**。每条机器指令对应一段微程序，微程序由若干条微指令组成。注意区分：机器指令存放在主存中，微指令是控制信号的集合。

> [!faq] 一条机器指令对应多少条微指令？</br>A. 一条</br>B. 若干条</br>C. 多条微程序</br>D. 一个微命令
> B。**一条机器指令对应一段微程序**，一段微程序由**若干条微指令**组成。微指令是最小单位，多条微指令按顺序组成微程序，实现一条机器指令的功能。

> [!faq] 微命令和微操作的关系是？</br>A. 一条微命令对应多个微操作</br>B. 多条微命令对应一个微操作</br>C. 一一对应</br>D. 无对应关系
> C。微命令和微操作**一一对应**。微命令是控制部件向执行部件发出的控制命令，微操作是微命令的操作过程。每个微命令触发一个微操作。

> [!faq] 以下哪种微操作可以编码表示？</br>A. 相容性微操作</br>B. 互斥性微操作</br>C. 同时执行的微操作</br>D. 并行执行的微操作
> B。**互斥性微操作**（不能同时执行的微操作）可以编码表示，因为它们不会同时需要。相容性微操作（可以同时执行）必须各占一位，采用直接表示法。

> [!faq] 水平型微指令和垂直型微指令的主要区别是？</br>A. 微指令字长度</br>B. 并行操作能力</br>C. 控制存储器容量</br>D. 微程序数量
> B。**并行操作能力**是主要区别。水平型微指令一次能定义并执行多个并行操作微命令，并行能力强；垂直型微指令一次只能执行1-2个微命令，并行能力弱。

> [!faq] 取指微程序的入口地址一般是？</br>A. 由PC指定</br>B. 控存的0号单元</br>C. 由IR指定</br>D. 任意地址
> B。取指微程序的入口地址一般为**控存的0号单元**。机器启动时，自动将0号地址送μMAR，执行取指微程序，取出机器指令后，由操作码决定后续微程序入口。

> [!faq] 微地址形成方法中，计数器方式的主要缺点是？</br>A. 微指令字长</br>B. 不能实现多路并行转移</br>C. 速度慢</br>D. 控存容量大
> B。计数器方式的主要缺点是**不能实现两路以上的并行微程序转移**。因为顺序执行时只能线性增加地址，灵活性差，不利于提高执行速度。多路转移方式能实现多路分支。

### 二、简答题

> [!faq] 简述微程序控制器的基本思想。
> 微程序控制器的基本思想是**用软件方法设计硬件**。把操作控制信号编制成微指令，存放到控制存储器里。运行时，从控存中取出微指令，产生指令运行所需的操作控制信号。这样将复杂的控制逻辑转化为存储在控存中的微程序。

> [!faq] 微指令通常包含哪两部分信息？各有什么作用？
> 微指令包含两大部分：(1)**操作控制字段**（微操作码字段）：产生某一步操作所需的各个微操作控制信号，某位为1表示发出该微命令；(2)**顺序控制字段**（微地址码字段）：控制产生下一条要执行的微指令地址，保证微指令连续执行。

> [!faq] 比较微命令的三种编码方法（直接表示法、编码表示法、混合表示法）。
> (1)**直接表示法**：操作控制字段各位直接控制，不需译码。优点是简单直观、并行性强、速度快；缺点是微指令字长。(2)**编码表示法**：将相斥微命令分组编码，通过译码输出控制信号。优点是微指令字短；缺点是增加译码电路、速度减慢。(3)**混合表示法**：结合前两种，兼顾字长和速度。

> [!faq] 说明微程序控制器的工作流程。
> 微程序控制器工作流程：(1)执行**取指微程序**（入口地址通常为控存0号单元），取出机器指令存入IR；(2)根据机器指令**操作码形成微程序入口地址**；(3)从控存逐条取出微指令并执行；(4)微程序执行完毕，下址回到取指微程序入口，继续取下一条机器指令。循环往复直到程序结束。

> [!faq] 相容性微操作和互斥性微操作有什么区别？在微指令编码中如何处理？
> **相容性微操作**：能够同时或在同一个节拍内并行执行的微操作，**必须各占一位**采用直接控制。**互斥性微操作**：不能同时或不能在同一个节拍内并行执行的微操作，可以**编码表示**，一组互斥微操作只需一个字段的几位编码。正确区分和处理这两类微操作是微程序设计的关键。

### 三、综合题

> [!faq] 微地址寄存器有6位(μA5-μA0)，三种判别测试P1、P2、P3：(1)执行取指微指令后，按IR的OP字段(IR3-IR0)进行16路分支；(2)执行条件转移微程序时，按进位标志C进行2路分支；(3)执行控制台指令微程序时，按IR4、IR5进行4路分支。写出微地址转移逻辑表达式。
> 分析：P1用IR3-IR0修改μA3-μA0（16路）；P2用C修改μA0（2路）；P3用IR4、IR5修改μA5、μA4（4路）。考虑时间因素T4，表达式为：μA5=P3·IR5·T4；μA4=P3·IR4·T4；μA3=P1·IR3·T4；μA2=P1·IR2·T4；μA1=P1·IR1·T4；μA0=P1·IR0·T4+P2·C·T4。注意μA0需两个条件叠加，用与或非门实现。

> [!faq] 某微程序控制器，控存容量为512×48位，微指令采用水平型格式，控制转移条件共4个，采用断定方式形成下址。请设计微指令格式。
> 分析：控存512单元需9位地址；转移条件4个需判别测试字段2位（可编码4种测试）；控制字段48-9-2=37位。微指令格式：[操作控制字段(37位)][下址字段(9位)][判别测试字段(2位)]。注意：断定方式下址直接由微指令给出，转移时通过测试修改部分位。
