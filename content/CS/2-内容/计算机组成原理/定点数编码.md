# 定点数编码

> [!important] 本章考试权重
> 定点数编码是基础章节，约占8-10分，常考题型包括：机器码转换、表示范围计算。

## 无符号数

- 只表示正数和0
- n位表示范围：0 ～ 2^n - 1

```
例：8位无符号数范围
最小值：00000000 = 0
最大值：11111111 = 255
范围：0 ~ 255
```

## 有符号数编码

### 原码表示

**定义**：
- 最高位为符号位（0正1负）
- 其余位为数值位

**范围**：-(2^(n-1)-1) ～ +(2^(n-1)-1)

**缺点**：
- 0有两种表示（+0和-0）
- 减法运算复杂

### 反码表示

**定义**：
- 正数：与原码相同
- 负数：符号位不变，数值位取反

**范围**：-(2^(n-1)-1) ～ +(2^(n-1)-1)

### 补码表示（最常用）

**定义**：
- 正数：与原码相同
- 负数：反码 + 1（末位加1）

**范围**：-2^(n-1) ～ +(2^(n-1)-1)

**优点**：
- 0只有一种表示
- 减法可转换为加法

### 移码表示

**定义**：补码的符号位取反

**用途**：主要用于浮点数的阶码表示

**优点**：便于比较大小（编码大小顺序与真值大小顺序一致）

## 机器码转换规则速记表

| 真值 | 原码 | 反码 | 补码 | 移码 |
|------|------|------|------|------|
| **正数** | 符号位0 + 数值位不变 | 同原码 | 同原码 | 符号位取反（变1），数值位同补码 |
| **负数** | 符号位1 + 数值位不变 | 符号位1 + 数值位**取反** | 反码 + 1（末位加1） | 符号位取反（变0），数值位同补码 |
| **0** | `+0`=全0, `-0`=100...0 | `+0`=全0, `-0`=111...1 | **唯一**：全0 | **唯一**：100...0 |

> [!warning] 超级易错点
> 1. **补码求 [-x]补**：不是只对数值位取反加1，而是**连同符号位一起**取反加1！
> 2. **移码 = 补码的符号位取反**，其余位一模一样。不是补码整体取反！
> 3. **0的补码和移码都只有一种表示**，原码和反码有两种。
> 4. 补码的 `100...0` 表示 -2^(n-1)，不是 -0！

## 机器码转换例题

### 例题1：正数的转换

**已知**：设字长为5位，X = +1011

**求**：[X]原、[X]反、[X]补、[X]移

**解**：
- [X]原 = **0**1011（正数，符号位0，数值位不变）
- [X]反 = **0**1011（正数反码同原码）
- [X]补 = **0**1011（正数补码同原码）
- [X]移 = **1**1011（移码 = 补码符号位取反，0→1）

### 例题2：负数的转换

**已知**：设字长为5位，X = -1011

**求**：[X]原、[X]反、[X]补、[X]移

**解**：
- 第一步：写出对应正数 +1011 的二进制 = 01011
- [X]原 = **1**1011（负数，符号位1，数值位不变）
- [X]反 = **1**0100（符号位1，数值位1011取反得0100）
- [X]补 = **1**0101（反码0100 + 1 = 0101）
- [X]移 = **0**0101（补码符号位取反，1→0）

验证：补码转真值，最高位是1表示负数。对10101连同符号位取反加1：01010 + 1 = 01011 = +11，所以真值为 -1011。✓

### 例题3：0的转换

**已知**：设字长为5位，X = 0

**求**：+0和-0的各种机器码

**解**：

| 编码 | [+0] | [-0] |
|------|------|------|
| 原码 | 00000 | 10000 |
| 反码 | 00000 | 11111 |
| 补码 | **00000** | **00000**（唯一） |
| 移码 | **10000** | **10000**（唯一） |

> [!warning] 易错点
> 补码中 `10000`（5位）表示的真值是 **-16**，不是 -0！因为补码没有 -0。
> 同理，8位补码中 `10000000` = **-128**。

## 补码表示范围速查表

### 8位补码表示范围

| 类型 | 最小值 | 最大值 | 范围 |
|------|--------|--------|------|
| 8位无符号数 | 00000000 = 0 | 11111111 = 255 | 0 ~ 255 |
| 8位原码整数 | 11111111 = -127 | 01111111 = +127 | -127 ~ +127 |
| 8位反码整数 | 10000000 = -127 | 01111111 = +127 | -127 ~ +127 |
| **8位补码整数** | **10000000 = -128** | **01111111 = +127** | **-128 ~ +127** |

### 16位补码表示范围

| 类型 | 最小值 | 最大值 | 范围 |
|------|--------|--------|------|
| 16位原码整数 | -32767 | +32767 | -(2^15 - 1) ~ +(2^15 - 1) |
| **16位补码整数** | **-32768** | **+32767** | **-2^15 ~ +(2^15 - 1)** |

### 通用公式

- n位**原码/反码**整数范围：-(2^(n-1) - 1) ~ +(2^(n-1) - 1)
- n位**补码**整数范围：**-2^(n-1)** ~ +(2^(n-1) - 1)
- 补码比原码多表示一个负数，这个多出来的数就是 `100...0` = -2^(n-1)

## 移码与补码的关系

### 核心结论

> **移码和补码的数值位完全相同，只有符号位相反。**

8位移码与补码对照表：

| 真值 | 补码 | 移码 |
|------|------|------|
| +127 | 01111111 | 11111111 |
| +1 | 00000001 | 10000001 |
| 0 | 00000000 | 10000000 |
| -1 | 11111111 | 01111111 |
| -127 | 10000001 | 00000001 |
| -128 | 10000000 | 00000000 |

### 为什么移码便于比较大小？

移码的编码大小顺序和真值的大小顺序**完全一致**：
- 移码中 `11111111` > `10000001` > `10000000` > `01111111` > `00000000`
- 对应真值：`+127` > `+1` > `0` > `-1` > `-128`

所以比较两个浮点数的阶码时，直接比较移码的二进制大小即可，不需要额外转换。

## 定点数表示范围计算例题

### 例题4：16位定点数表示范围

**已知**：设机器字长16位，定点表示，尾数15位（含符号位）

**求**：(1) 定点原码整数表示时，最大正数和最小负数是多少？
       (2) 定点原码小数表示时，最大正数和最小负数是多少？

**解**：

**(1) 定点原码整数**
- 最大正数：`0 111 111 111 111 111`
  - x = +(2^15 - 1) = +32767
- 最小负数：`1 111 111 111 111 111`
  - x = -(2^15 - 1) = -32767

**(2) 定点原码小数**
- 最大正小数：`0 111 111 111 111 111`
  - x = 1 - 2^-15 = 0.999969482...
- 最小负小数：`1 111 111 111 111 111`
  - x = -(1 - 2^-15)

> [!note] 关键区别
> - 定点整数：小数点固定在最后一位之后
> - 定点小数：小数点固定在符号位之后

## 考试真题精选

> [!faq] 设机器字长8位，x=-127，则[x]补为？</br>A. 10000001</br>B. 11111111</br>C. 10000000</br>D. 01111111
> A。-127的原码为11111111，补码为原码除符号位外取反加1：10000000+1=10000001。注意-128是特殊情况，其补码为10000000，在原码中无法表示。

> [!faq] 设机器字长8位，x=-1，则[x]补、[x]反、[x]移分别为？
> [x]原=10000001，[x]反=11111110，[x]补=11111111，[x]移=01111111。移码与补码数值位相同，符号位相反。

> [!faq] 8位补码整数10000000表示的真值是多少？
> -128。补码中没有"-0"这个概念，10000000这个编码被用来表示-128，这是补码比原码多表示的一个负数。

> [!faq] 设字长8位，分别写出-128、-1、+1、+127的原码、反码、补码、移码。
> -128：原码/反码无法表示，补码=10000000，移码=00000000。[-1]原=11111111，[-1]反=11111110，[-1]补=11111111，[-1]移=01111111。+1：四种编码均为00000001，移码为10000001。+127：原码/反码/补码=01111111，移码=11111111。

> [!faq] 补码比原码多表示一个负数，这个数是什么？其补码形式是什么？
> 这个数是-2^(n-1)，其补码形式为100...0（符号位为1，其余位全0）。例如8位补码中10000000表示-128，16位补码中1000000000000000表示-32768。
