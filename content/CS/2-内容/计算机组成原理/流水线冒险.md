# 流水线冒险

> [!warning]
> 三种冒险的名称和处理方式是考试高频考点，必须熟练掌握！

---

## 冒险概述

**流水线冒险（Hazard）**：流水线执行过程中，由于各种原因导致后续指令无法按预期时钟周期执行的现象。

三种冒险类型：
1. **结构冒险（Structural Hazard）**：资源相关
2. **数据冒险（Data Hazard）**：数据相关
3. **控制冒险（Control Hazard）**：控制相关

---

## 结构冒险（资源相关）

### 定义与原因

**原因**：多条指令进入流水线后，在同一时钟周期内**争用同一功能部件**。

### 典型示例

**示例1**：IF 段和 MEM 段都要访问存储器，单端口存储器无法同时满足。

```
时钟周期:    1     2     3     4     5
           ┌─────┬─────┬─────┬─────┬─────
指令I1      │ IF  │ ID  │ EX  │ MEM │ WB
指令I2      │     │ IF  │ ID  │ EX  │ MEM
           └─────┴─────┴─────┴─────┴─────
问题：在第4周期，I1在MEM段访问存储器，
      I2在IF段也要访问存储器 → 冲突！
```

**示例2**：两条指令同时使用同一个 ALU。

### 解决方法

| 方法 | 说明 | 优缺点 |
|------|------|--------|
| **插入停顿（Stall）** | 后续指令拖一拍再推进（插入气泡） | 简单但降低效率 |
| **增设功能部件** | 增设资源（如指令 Cache 和数据 Cache 分离） | 效果好，成本高 |

> [!tip]
> 指令 Cache 和数据 Cache 分离（哈佛结构思想）可以有效解决 IF 和 MEM 同时访存的结构冒险。

---

## 数据冒险（数据相关）

### 定义与原因

**原因**：指令之间存在**数据依赖**，后续指令需要前一条指令的结果。

### 三种类型

| 类型 | 英文 | 含义 | 在简单流水线中是否出现 |
|------|------|------|----------------------|
| **RAW** | Read After Write | 写后读：后面指令用到前面指令所写的数据 | **最常见！** |
| **WAR** | Write After Read | 读后写：后面指令覆盖前面指令所读的单元 | 简单流水线中**不会出现**（按序执行） |
| **WAW** | Write After Write | 写后写：两条指令写同一个单元 | 简单流水线中**不会出现**（按序执行） |

### RAW 示例

```asm
ADD R1, R2, R3   ; R1 = R2 + R3  （写R1）
SUB R4, R1, R5   ; R4 = R1 - R5  （读R1，但ADD还未写回）
```

问题分析：
- ADD 指令在第5周期（WB段）才将结果写入 R1
- SUB 指令在第3周期（ID段）就要读 R1
- 此时 R1 中还是旧值，导致数据错误

### WAR 示例

```asm
STO M(x), R3     ; 将 R3 存入存储器（读R3）
ADD R3, R4, R5   ; R3 = R4 + R5  （写R3）
```

> [!warning]
> WAR 相关在简单按序执行的流水线中**不会出现**，但在乱序执行的流水线中可能出现。

### WAW 示例

```asm
MUL R3, R1, R2   ; R3 = R1 × R2  （写R3）
ADD R3, R4, R5   ; R3 = R4 + R5  （写R3）
```

> [!warning]
> WAW 相关在简单按序执行的流水线中**不会出现**，但在乱序执行或超标量流水线中可能出现。

### 解决方法

| 方法 | 说明 | 效果 |
|------|------|------|
| **插入停顿（Stall）** | 推后读操作，等待前指令写回 | 简单但降低效率 |
| **数据前递（Forwarding/Bypassing）** | EX 段结果直接传递给下一条指令的 EX 段，不需要等到 WB 段 | 显著减少停顿 |
| **编译器调度** | 调整指令顺序，插入无关指令填充 | 无硬件开销 |

### 数据前递原理

```
正常流程：ADD → WB（写回） → SUB → ID（读）
前递方式：ADD → EX（结果） ──直接传递──→ SUB → EX（使用）

      ADD的EX段输出 ──┐
                      │
                      └──→ SUB的EX段输入
```

> [!tip]
> **RAW（写后读）是真数据相关**，在简单流水线中最常见，也是考试最爱考的！

## 控制冒险（控制相关）

### 定义与原因

**原因**：**转移指令**改变程序执行顺序，导致流水线中后续取出的指令可能无效。

### 典型示例

```asm
BEQ R1, R2, Label  ; 若 R1=R2 则跳转到 Label（是否跳转需等到 EX 段才能确定）
ADD R3, R4, R5     ; 不确定该不该执行这条指令
```

问题分析：
- 分支指令是否跳转需要等到 EX 段才能确定
- 但流水线已经取了后续指令（ADD）
- 如果分支成功跳转，已取的 ADD 指令就是无效的，需要清空流水线

### 解决方法

| 方法 | 说明 | 效果 |
|------|------|------|
| **延迟转移法** | 转移指令后的指令（延迟槽）无论是否跳转都执行 | 编译器配合，效果好 |
| **转移预测法** | 预测是否跳转，预测错误则清空流水线 | 动态预测效果好 |
| **插入停顿** | 分支后插入 NOP 直到确定跳转方向 | 最简单但效率低 |

### 延迟转移原理

```asm
BEQ R1, R2, Label  ; 分支指令
NOP                ; 延迟槽（无论跳转与否都执行）
ADD R3, R4, R5     ; 真正的后续指令

优化后：
BEQ R1, R2, Label
ADD R3, R4, R5     ; 将 ADD 放入延迟槽执行（与分支无关的指令）
```

### 转移预测

| 预测类型 | 说明 | 准确率 |
|----------|------|--------|
| **静态预测** | 总是预测跳转或不跳转 | 约50-70% |
| **动态预测** | 根据历史记录预测（如 BHT） | 约90%+ |

## 冒险判断例题（必考！）

> [!warning]
> 判断数据冒险类型（RAW/WAR/WAW）是**考试高频考点**！

### 例题：判断数据冒险类型

**题目**：判断以下三组指令各存在哪种类型的数据相关。

```asm
(1) I1: ADD R1, R2, R3    ; (R2)+(R3)→R1
    I2: SUB R4, R1, R5    ; (R1)-(R5)→R4

(2) I3: STO M(x), R3      ; (R3)→M(x)
    I4: ADD R3, R4, R5    ; (R4)+(R5)→R3

(3) I5: MUL R3, R1, R2    ; (R1)×(R2)→R3
    I6: ADD R3, R4, R5    ; (R4)+(R5)→R3
```

**解答**：

| 组别 | 冒险类型 | 分析 |
|------|----------|------|
| **第(1)组** | **RAW（写后读）** | I1写R1，I2读R1。I2在I1写回前就读R1，发生RAW相关 |
| **第(2)组** | **WAR（读后写）** | I3读R3存入存储器，I4写R3。I4在I3读R3前就写R3，发生WAR相关 |
| **第(3)组** | **WAW（写后写）** | I5和I6都写R3。若I6先完成，导致R3内容错误，发生WAW相关 |

> [!tip]
> **判断技巧**：
> - **RAW**：后指令读前面指令写的寄存器 → **最常见！**
> - **WAR**：后指令写前面指令读的寄存器 → 简单流水线不出现
> - **WAW**：两条指令写同一寄存器 → 简单流水线不出现

## 三种冒险综合对比表

| 冒险类型 | 原因 | 示例 | 主要解决方法 |
|----------|------|------|--------------|
| **结构冒险** | 争用同一功能部件 | IF和MEM同时访存 | 增设功能部件 |
| **数据冒险** | 数据依赖（RAW最常见） | ADD后SUB读结果 | 数据前递 |
| **控制冒险** | 转移指令改变顺序 | 分支指令后指令可能无效 | 转移预测 |

## 本章考试常见题型

### 一、选择题

> [!faq] 流水线中，多条指令争用同一功能部件发生的冲突叫什么冒险？</br>A. 数据冒险</br>B. 控制冒险</br>C. 结构冒险</br>D. 时间冒险
> C。**结构冒险（资源相关）**是多条指令进入流水线后在同一时钟周期内争用同一功能部件发生的冲突。例如IF段和MEM段同时访问存储器。解决方法：增设功能部件或插入停顿。

> [!faq] RAW数据冒险的含义是什么？</br>A. 读后写</br>B. 写后读</br>C. 写后写</br>D. 读后读
> B。**RAW（Read After Write写后读）**：后面指令用到前面指令所写的数据。这是最常见的数据冒险类型，在简单流水线中会出现。WAR是读后写，WAW是写后写，简单流水线中不出现。

> [!faq] 解决控制冒险（分支指令）的方法不包括？</br>A. 延迟转移法</br>B. 转移预测法</br>C. 数据前递</br>D. 插入停顿
> C。**数据前递**是解决**数据冒险**的方法，不是控制冒险的解决方法。控制冒险的解决方法有：(1)延迟转移法；(2)转移预测法；(3)插入停顿。

> [!faq] 以下哪种数据冒险在简单流水线中最常见？</br>A. WAR</br>B. WAW</br>C. RAW</br>D. 都常见
> C。**RAW（写后读）**是简单流水线中最常见的数据冒险类型，因为简单流水线按序执行，WAR和WAW不会出现。

### 二、简答题

> [!faq] 简述流水线三种冒险的成因和解决方案。
> 三种冒险：(1)**结构冒险**：多条指令争用同一功能部件。解决：插入停顿或增设功能部件（如指令Cache和数据Cache分离）；(2)**数据冒险**：指令间数据依赖（RAW最常见）。解决：插入停顿、数据前递、编译器调度；(3)**控制冒险**：转移指令导致后续指令可能无效。解决：延迟转移、转移预测、插入停顿。

> [!faq] 什么是数据冒险中的RAW、WAR、WAW？
> 数据冒险三种类型：(1)**RAW（写后读）**：后指令读前面指令写的数据，是最常见类型，简单流水线会出现；(2)**WAR（读后写）**：后指令覆盖前面指令读的单元，简单流水线不出现（按序执行）；(3)**WAW（写后写）**：两条指令写同一单元，简单流水线不出现，乱序执行会出现。

### 三、判断题

> [!faq] 判断以下指令序列的数据冒险类型：I1: ADD R1,R2,R3；（R2)+(R3)→R1；I2: SUB R4,R1,R5；（R1)-(R5)→R4。
> **RAW（写后读）相关**。I1写R1，I2读R1。由于流水线重叠执行，I2在I1写回R1前就读R1，发生写后读冲突。这是最常见的数据冒险类型。

> [!faq] 判断以下指令序列的数据冒险类型：I3: STO M(x),R3；（R3)→M(x)；I4: ADD R3,R4,R5；（R4)+(R5)→R3。
> **WAR（读后写）相关**。I3读R3存入存储器，I4写R3。如果I4在I3读R3前就写R3，导致I3读到的数据错误。这种相关在简单按序执行的流水线中不会出现。

> [!faq] 判断以下指令序列的数据冒险类型：I5: MUL R3,R1,R2；（R1)×(R2)→R3；I6: ADD R3,R4,R5；（R4)+(R5)→R3。
> **WAW（写后写）相关**。I5和I6都写R3。如果I6在I5写R3前就写R3，导致R3内容错误。简单按序执行流水线中不会出现，但在乱序执行超标量流水线中可能出现。
