# 控制方式

控制方式是指**控制不同操作序列时序信号的方法**。

---

## 同步控制方式

### 基本原理

**同步控制方式**：在任何情况下，已定的指令在执行时所需的机器周期数和时钟周期数都是**固定不变**的。

各微操作时长只受统一的基准时钟信号控制：`TCP = TCLK`

**特点**：
- CP 与时钟信号同步（CP = CLK）
- **控制简单、时间浪费大**
- 适合 **CPU 内部**的微操作定时（各微操作时延相近）

### 三种实现方案

| 方案 | 说明 | 优缺点 |
|------|------|--------|
| **完全统一的机器周期** | 所有指令具有相同的节拍电位数和节拍脉冲数 | 简单规整，但简单指令浪费时间 |
| **不定长机器周期** | 大多数操作在短周期完成，某些紧张操作延长周期 | 时间利用合理，控制稍复杂 |
| **中央+局部控制结合** | 大部分指令在固定周期完成（中央控制）；少数复杂指令（乘除、浮点）另设时序（局部控制） | 高效处理复杂指令 |

### 时序安排示例

**中央控制与局部控制结合**：

```
普通指令:  M1(取指) → M2(执行) → M1(下一条)
                    ↑
                  中央控制

乘法指令:  M1(取指) → M2(准备) → [局部控制: M2'循环n次] → M3(结束)
                              ↑
                           局部控制（乘法步数不固定）
```

### 适用场景

- CPU **内部**微操作定时
- 各微操作时延**相近**的情况
- 操作动作**较少**的微型机

> [!tip]
> 同步控制方式控制简单，但可能造成时间浪费，因为要以最慢的操作为基准定时。

> [!warning]
> 同步控制的缺点是**时间可能有浪费**！因为要以最慢的微操作为基准来定时。

## 异步控制方式（应答方式 / 握手方式）

### 基本原理

**异步控制方式**：每条指令、每个操作控制信号**需要多少时间就占用多少时间**。

各微操作的时长只受专门的**联络信号（应答信号）**控制：`TCP = T收到应答 - T发出命令`

**特点**：
- CP 与应答信号同步（CP = ACK）
- **时间浪费小、控制复杂**
- 适合 **CPU 与外部设备**的微操作定时（时延相差较大）

### 工作方式

1. **无固定 CPU 周期数**：指令周期可由数目不等的机器周期组成
2. **应答方式（握手方式）**：控制器发出操作信号后，等待执行部件发回"回答"信号再开始新操作

### 时序关系

```
控制器              执行部件
    │                  │
    │──── 命令信号 ────│
    │                  │
    │                  │  （执行操作）
    │                  │
    │──── 应答信号 ────│
    │                  │
    │  （开始下一操作） │
```

### 特点分析

| 优点 | 缺点 |
|------|------|
| 时间效率高，无浪费 | 控制复杂，硬件多 |
| 适应各种速度设备 | 电路设计难度大 |
| 无需统一时序基准 | 增加应答信号传输时间 |

### 适用场景

- **CPU 与外部设备**的微操作定时
- 各微操作时延**相差较大**的情况
- 外设速度差异大的系统

---

## 联合控制方式（半同步方式）

### 基本原理

**联合控制方式**：同步控制和异步控制相结合，又称**半同步方式**。

各微操作的时长受**基准时钟信号及联络信号共同控制**：`TCP = k × TCLK`

- `k = 1` 时：同步控制
- `k > 1` 时：异步控制（等待应答信号）

**特点**：
- 用微操作命令指明当前控制方式
- **时间浪费小、控制相对简单**
- 适合 CPU 的**所有微操作**定时
- 当需要等待外部设备时（如读内存），若联络信号 `mfc = 0`（未完成），则封锁 CP，等待完成后再继续

### 两种实现形式

| 形式 | 说明 |
|------|------|
| **固定周期 + 应答信号** | 大部分操作在固定周期完成，某些时间不确定的操作以"应答"信号结束 |
| **固定节拍 + 不固定周期数** | 机器周期节拍脉冲数固定，但各指令机器周期数不固定 |

### 典型应用：微程序控制器

微程序控制器采用联合控制方式：
- **节拍脉冲数固定**：一个微指令周期有固定的节拍脉冲
- **机器周期数不固定**：不同机器指令对应不同长度的微程序

### 读写内存示例

```
CPU 发出读命令:
    │
    │  发出 RD 命令（同步）
    │
    │  等待 READY 信号...
    │     （异步：等待存储器响应）
    │
    │  收到 READY=1
    │
    │  读取数据完成
```

**控制信号逻辑**：
```
CP = func(WMFC, CLK, mfc)

当 WMFC=0: CP = CLK（同步方式）
当 WMFC=1: CP = mfc · CLK（等待 mfc=1 才继续）
```

### 适用场景

- **通用计算机系统**
- 需要**兼顾效率和复杂度**
- CPU 的**所有微操作**定时

## 三种控制方式综合对比表（考试重点！）

| 控制方式 | 定时依据 | CPU周期数 | 优点 | 缺点 | 适用场景 |
|----------|----------|-----------|------|------|----------|
| **同步控制** | 统一时钟 | 固定 | 控制简单、实现容易 | 时间浪费大 | CPU内部、微型机 |
| **异步控制** | 应答信号 | 不固定 | 时间效率高、无浪费 | 控制复杂、硬件多 | CPU与外部、大型机 |
| **联合控制** | 时钟+应答 | 部分固定 | 兼顾效率和复杂度 | 设计较复杂 | 通用计算机 |

> [!tip]
> 微程序控制器通常采用：**机器周期的节拍脉冲固定，但各指令的机器周期数不固定**。这也是一种联合控制的变体。

## 本章考试常见题型

### 一、选择题

> [!faq] 同步控制方式的主要缺点是什么？</br>A. 控制复杂</br>B. 时间浪费</br>C. 硬件成本高</br>D. 无法处理外设
> B。同步控制方式的缺点是**时间浪费大**，因为所有操作必须以最慢的操作为基准来定时，简单操作也要等待同样长的时间。

> [!faq] 以下哪种情况最适合采用异步控制方式？</br>A. CPU内部运算</br>B. 访问高速缓存</br>C. CPU访问低速外设</br>D. ALU加减运算
> C。异步控制方式适合**CPU与外部设备**的微操作定时，尤其是外设速度差异较大、难以统一定时的情况。CPU内部运算时延相近，适合同步控制。

> [!faq] 联合控制方式又称什么方式？</br>A. 同步方式</br>B. 异步方式</br>C. 半同步方式</br>D. 全同步方式
> C。联合控制方式又称**半同步方式**，是同步控制和异步控制相结合的方式，兼具两者的优点。

### 二、简答题

> [!faq] 什么是联合控制方式？它有什么特点？
> 联合控制方式是**同步控制和异步控制相结合**的方式（又称半同步方式）。特点：(1)大部分操作安排在固定机器周期中完成；(2)对某些时间难以确定的操作以执行部件的"应答"信号作为结束标志；(3)机器周期的节拍脉冲数固定，但各指令的机器周期数不固定。优点是兼顾效率和复杂度，适合通用计算机系统。

> [!faq] 简述同步控制方式的三种实现方案。
> 同步控制方式的三种实现方案：(1)**完全统一的机器周期**：所有指令具有相同的节拍电位数和节拍脉冲数，简单规整但浪费时间；(2)**不定长机器周期**：大多数操作在短周期完成，某些紧张操作延长周期，时间利用合理；(3)**中央+局部控制结合**：大部分指令在固定周期完成，少数复杂指令另设时序，高效处理复杂指令。
