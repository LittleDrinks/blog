# 指令格式设计题（第4章设计题）

> [!warning] 考试重点
> 扩展操作码设计是**常考设计题**，必须掌握计算方法！

## 扩展操作码核心公式

假设指令字长n位，地址码各占k位：

```
三地址指令操作码位数 = n - 3k
二地址指令操作码位数 = n - 2k
一地址指令操作码位数 = n - k
零地址指令操作码位数 = n

扩展规则：每种类型指令必须预留扩展标志
```

### 例题1：扩展操作码数量计算

**题目：**
> 某计算机指令字长16位，每个地址码占4位。
> 若设计三地址指令15条，二地址指令14条，一地址指令31条。
> 问：最多还能设计多少条零地址指令？

**解答：**
```
分析：
- 地址码各4位，三地址指令的操作码 = 16 - 12 = 4位
- 二地址指令的操作码 = 16 - 8 = 8位（扩展4位）
- 一地址指令的操作码 = 16 - 4 = 12位（扩展4位）
- 零地址指令的操作码 = 16位（扩展4位）

计算扩展空间：
第1步：三地址指令
       4位操作码可编码 2^4 = 16 种
       用了15种，预留 16 - 15 = 1 种作为扩展标志

第2步：二地址指令
       从1个扩展点扩展4位，可编码 1 × 2^4 = 16 种
       用了14种，预留 16 - 14 = 2 种作为扩展标志

第3步：一地址指令
       从2个扩展点各扩展4位，可编码 2 × 2^4 = 32 种
       用了31种，预留 32 - 31 = 1 种作为扩展标志

第4步：零地址指令
       从1个扩展点扩展4位，可编码 1 × 2^4 = 16 种

答：最多还能设计 16 条零地址指令
```

> [!tip] 计算模板
> ```
> 零地址指令数 = [(2^(n-3k) - 三地址数) × 2^k - 二地址数] × 2^k - 一地址数] × 2^k
> ```

### 例题2：扩展操作码方案验证

**题目：**
> 某计算机指令字长32位，地址码各8位。
> 已设计：
> - 三地址指令4条
> - 二地址指令16条
> - 一地址指令64条
> - 零地址指令32条
>
> 问：该设计方案是否可行？

**解答：**
```
计算可用编码空间：
- 三地址操作码 = 32 - 24 = 8位，可编码 2^8 = 256 种
- 三地址用了4条，预留 256 - 4 = 252 种扩展

- 二地址从252种扩展8位，可编码 252 × 2^8 = 64512 种
- 二地址用了16条，预留 64512 - 16 = 64496 种扩展

- 一地址从64496种扩展8位，可编码 64496 × 2^8 = 16511072 种
- 一地址用了64条，预留远超需要的32条

结论：方案可行，零地址指令空间绰绰有余
```

### 例题3：高频指令优先设计

**题目：**
> 某计算机指令字长16位，地址码各4位。
> 已知指令使用频率：
> - 三地址指令：5条（最高频）
> - 二地址指令：10条（中频）
> - 一地址指令：20条（低频）
>
> 设计最优扩展操作码方案。

**解答：**
```
设计思路：高频指令用短操作码

(1) 三地址指令（最高频）
    操作码4位，分配0000~0100（5条）
    预留0101~1111共11种作为扩展标志

(2) 二地址指令（中频）
    从11个扩展点扩展，操作码变成8位
    可编码 11 × 16 = 176 种
    分配10条，预留166种

(3) 一地址指令（低频）
    从166个扩展点扩展，操作码变成12位
    可编码 166 × 16 = 2656 种
    分配20条，预留2636种

该方案充分利用了短操作码的优势，高频指令编码紧凑。
```

> [!warning] 设计要点
> 1. **高频指令优先分配短操作码**
> 2. **每种类型指令必须预留扩展标志**
> 3. **短操作码不能是长操作码的前缀**
